# DomEconomy

Minecraft 1.21.x (Paper API) 環境向けに設計された、堅牢かつ低負荷なサーバー専用のデジタル銀行＆物理通貨システムプラグインです。
従来の仮想チェストを使用した銀行プラグインの仕様を根本から見直し、データの一貫性（ACID特性）を重視した安全な取引モデルを実装しています。

---

## 🏛️ 特徴

- **ACID特性を重視した同期取引モデル**  
  お引き出し（WITHDRAW）や預け入れのトランザクションはすべて同期的にVault APIを介して行われ、成功が確定した段階で初めてアイテムの増減を行います。サーバーの予期せぬシャットダウンや回線切断を悪用した複製バグ（デュープ）を排除します。
- **一括自動預け入れ（チャージ）システム**  
  仮想チェストに物理通貨を一時的に格納させるレガシーな預入れ仕様を廃止。インベントリを自動スキャンし、一括で口座にチャージする「預け入れ確定GUI方式」を導入しています。アイテムロストやセーブの時差を突いたグリッチが原理的に発生しません。
- **3D ATM端末システム（クリエイティブ専用）**  
  OP権限を保持する管理者（クリエイティブモード）のみがATMを設置・解体できます。非表示の `ArmorStand` とバリアブロックを同期させ、疑似的な3Dモデルとして表示させます。
- **超軽量設計（ゼロタイマー）**  
  定期的なデータ同期タスク（Scheduler）や不要な文字列結合を完全に排除。`InventoryHolder` の参照型チェックによる高速なGUI識別と、`record` クラスを用いた $O(1)$ 座標キャッシュを組み合わせることで、サーバーパフォーマンスへの影響を最小限に抑えています。
- **偽札製造の防止**  
  アイテムの価値判定に `CustomModelData` の参照を使用せず、PersistentDataContainer（PDC）に登録された特定の名前空間キー（`domeconomy:currency_value`）のみに依存するため、偽札をATMに投入するなどの不正行為を無効化します。

---

## 🛠️ コマンド

- `/bank`  
  自身のデジタル口座残高を確認します。
- `/bank atm [プレイヤー名]`  
  指定したプレイヤー（省略時は自身）にATM端末アイテムを付与します（OP専用 / `domeconomy.admin`）。
- `/atm`  
  ATMメニューを直接起動します（常設ATMがない場所でも利用可能、権限不要）。

## ⚙️ システム仕様

### 物理通貨 (PhysicalCurrency)
金塊（`GOLD_NUGGET`）をベースとし、PDCの `NamespacedKey` に対応する固有の価値を記憶しています。1円から1兆円までの14種類の通貨が定義されています。

### 取引安全性
- **取引上限の制限**: 浮動小数点数の丸め誤差や経済バックエンド側のオーバーフローを防止するため、1回あたりの最大取引額は `9,000,000,000,000円`（9兆円）に制限されています。
- **インベントリ空き容量の自動検証**: お引き出しの際、インベントリに紙幣を収容する空きスロットまたは同一のスタック可能スペースが不足している場合、取引自体を自動的にキャンセルします（現物ドロップによる第三者強奪トラブルの防止）。
- **完全なロールバック**: Vault取引が何らかの理由（経済プラグインの停止など）で失敗した場合、預け入れ操作中の通貨アイテムは即座にプレイヤーに返却されます。

## ⚠️ 現在確認されている仕様制限・既知の課題

当プラグインはメインスレッド上での整合性を最優先に設計されていますが、外部のシステムや運用方法によって、以下の仕様上の制限、またはエッジケースが残されています。

### 1. 経済バックエンドが非同期クエリを並行処理する場合の競合リスク
Vault APIは同期的なインターフェースとして定義されていますが、一部のMySQLをサポートする経済プラグインでは、内部のデータベース書き込みが非同期のクエリプールとして並行処理される場合があります。
サーバー負荷が極端に高い（TPS低下時）、または高レイテンシ（高ping）の環境下において、プレイヤーが高速な連打で取引を試みた場合、当プラグインが防ぐ取引チェックを越えた段階で外部データベース側での同時書き込みの不整合（マイナス残高や一時的なクエリキューの遅延など）が発生する可能性があります。
* ※当プラグインとしては一律に即時同期的解決を図っていますが、Vaultの下位にある経済実装側の非同期トランザクション特性に依存します。

### 2. 外部ブロック編集・補修プラグインによるATMの「亡霊化」
ATMの削除は `BlockBreakEvent` および `EntityDamageByEntityEvent` で検知されます。
しかし、以下のような「Spigotの標準的な破壊イベントをバイパスする処理」が実行された場合、土台となるバリアブロックのみが空気（AIR）に置換され、非表示の `ArmorStand` だけが空中に浮いた状態で永続的に取り残される可能性があります。
- `WorldEdit`（`//cut` や `//set air`）によるバリアブロックの消去
- ダンジョン自動生成、またはワールドリセット系プラグインによるブロックの一括復元・書き換え
- バリアブロックに対する保護領域を管理者が意図せずNMSレベルで書き換える処理

### 3. 経済サービスプラグイン無効化時における極めて限定的な強制払い戻し
`/stop` などのシャットダウンプロセスの最終盤において、当プラグインの `onDisable()` は全ての開いているATM画面を強制的にクローズしてトランザクションを解決（または返却）しようとします。
しかし、シャットダウンの順序において、別の依存経済プラグイン（例：EssentialsX等）がすでに無効化（`onDisable`）を終えてサービス登録が完全に解除されていた場合、その瞬間に預入れ（`DEPOSIT`）のGUIを開いていたプレイヤーの通貨は、デジタル口座に反映できず、アイテムの返却もできない状態となり消失します（不整合防止の安全弁により、NPEによるクラッシュは起きないようにガードをかけています）。
* **対策**: 管理者は、サーバーの再起動・停止コマンドを打つ数秒前に、あらかじめプレイヤーに対してログアウトや画面クローズを呼びかけることを推奨します。

### 4. クリエイティブモードのATM設置物直接破壊時の挙動
ATM（バリアブロック）はクリエイティブモードのOPが手動破壊した際にアイテムドロップが発生しないように設定（サバイバルにおけるドロップ仕様を完全に廃止）されています。
しかし、管理者がクリエイティブモード以外のゲームモードに変更した状態でバリアブロックを壊そうとした場合、一般プレイヤーと同様に保護が適用され、破壊することはできません。ATMの移設や解体を行う際は、必ずクリエイティブモードに切り替えて操作してください。
